# 分类分级基线说明

## 1. 适用范围

本基线用于数据库表和字段的初步分类分级，作为资产发现、规则命中和人工复核的起点。当前版本包含 5 个级别、33 个分类节点、95 个数据类型和 286 条识别规则，其中包括 95 条数据内容正则和 191 条元数据辅助规则，覆盖个人信息、业务信息、管理与安全信息、公共信息四个一级分类。

规则优先对字段样本值执行正则匹配，字段名、字段注释、字段类型、表名和表注释用于内容特征不足时的辅助判断。命中结果是治理建议，不直接构成法律或监管认定。

## 2. 主要依据

| 依据                                                   | 在模板中的用途                                                                                     |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| GB/T 43697-2024《数据安全技术 数据分类分级规则》       | 分类框架、分级影响对象、危害程度和重要/核心数据复核边界                                            |
| GB/T 35273-2020《信息安全技术 个人信息安全规范》       | 个人信息分类及敏感个人信息识别参考                                                                 |
| 《中华人民共和国个人信息保护法》第二十八条、第三十一条 | 生物识别、宗教信仰、特定身份、医疗健康、金融账户、行踪轨迹及不满十四周岁未成年人信息的高敏保护要求 |
| JR/T 0197-2020《金融数据安全 数据安全分级指南》        | 金融账户、支付鉴权、征信授信、交易与监管报送规则参考                                               |
| YD/T 3813-2020《基础电信企业数据分类分级方法》         | 通信内容、联系人、网络标识、上网和应用使用记录规则参考                                             |

行业标准用于补充通用字段词典，实际项目仍应优先采用所属行业主管部门最新发布的数据分类分级目录。

## 3. 分级口径

| 级别 | 名称         | 自动识别含义                                                                |
| ---- | ------------ | --------------------------------------------------------------------------- |
| L1   | 公开数据     | 已依法、依规公开或可对外提供，泄露通常不造成明显损害                        |
| L2   | 内部数据     | 一般内部业务和管理数据，外泄造成有限运营影响                                |
| L3   | 敏感数据     | 涉及个人权益或重要业务明细，需要最小化访问、脱敏和加密                      |
| L4   | 重要数据 | 可能造成严重危害，或属于高敏个人/业务数据；必须结合场景、规模和行业目录复核 |
| L5   | 核心数据     | 可能直接影响国家安全、国民经济命脉、重要民生或重大公共利益，必须人工认定    |

敏感个人信息不当然等同于重要数据或核心数据。因此登录密码、生物识别模板等默认归入 L4 保护级，只有主密钥材料等关键控制数据进入 L5 初筛；L4、L5 均需人工确认。

## 4. 规则设计

- 每个数据类型至少配置一条数据内容正则。身份证号、手机号、邮箱、银行卡、IP、MAC、车牌、VIN、数据库连接串等采用锚定结构正则；医疗、合同、监管报送等自由文本采用明确领域词组，不使用无约束的宽泛表达式。
- 聚合分类目录用于组织同一业务域，叶子数据类型保持单一语义和单一默认等级。宗教信仰、民族、政治面貌、国籍以及车辆标识、出行票务、出行轨迹等分别维护，不因初始等级相同而合并规则。
- 数据内容规则优先于元数据规则。强格式通常要求 80% 至 100% 的有效样本符合正则；领域文本通常要求 80% 以上样本包含稳定领域特征。
- 普通金额、短数字、验证码、账号、流水号等值脱离业务上下文后无法可靠区分，只匹配带格式前缀、协议头或结构键名的形式，其余交由元数据规则或人工复核。
- 所有日期、时间和格式化年月统一归入“时间信息”，不再依据字段用途区分出生时间、业务时间、有效期或维护时间。
- 出生日期不再与性别合并分类：出生日期归入“时间信息”，“性别”作为独立数据类型维护。
- 字段英文词典使用业务限定词，避免用裸 `name`、`address`、`token` 等高误报词；英文 `contains` 按下划线分词边界匹配，避免 `tag` 误命中 `stage_flag`。
- 中英文规则成对配置，分别匹配字段名和字段注释。
- 表级规则仅用于审计日志、监管报送、公开公告等表语义明确的场景。
- 字段名、字段注释、字段类型、表名和表注释属于确定性元数据规则，不配置命中率；冲突时按匹配方式、目标位置和实际命中关键词的具体度排序。
- 数据内容规则对字段样本执行正则匹配，命中率表示匹配样本数占有效样本数的比例；达到配置阈值后才视为命中。
- 新建规则默认选择“样本数据”、使用正则匹配并要求 100% 样本命中；切换为元数据目标后不保存命中率。
- 内置模板在 `classification-baseline-v8` 启动升级中同步；旧合并类型会被移除，其已关联字段恢复为待分类状态；自定义模板及内置模板副本不会被覆盖。

## 5. 人工复核要点

1. 判断数据是否已合法公开、是否可识别自然人，以及是否与其他字段组合后增强识别能力。
2. 结合数据规模、精度、时效性、聚合程度、覆盖人群和业务场景调整级别。
3. 对 L4、L5 命中项核对行业重要数据目录、监管要求和组织风险评估结果。
4. 对跨境、共享、委托处理和公开披露场景单独评估，不沿用存储态级别直接作出结论。
5. 定期分析误报、漏报和人工改判记录，更新字段词典及命中率。

## 6. 未命中规则归纳方法

`v6` 基线从未命中字段和已分类样本中抽取跨数据库、跨业务表可复用的内容结构与语义模式，而不是按单个样例字段逐条补词：

| 共性缺口                                   | 补充方式                                 | 适用边界                                                                               |
| ------------------------------------------ | ---------------------------------------- | -------------------------------------------------------------------------------------- |
| 客户、用户、账户、员工等主体外键           | 拆分为自然人、组织、账户租户三类主体标识 | 只匹配带明确主体前缀的标识，不匹配任意 `*_id`                                          |
| 订单、支付、注册等状态和渠道               | 分别维护“业务状态”和“业务渠道”           | 只匹配明确业务对象，不匹配泛化 `status`、`channel`                                     |
| 银行、医疗机构、部门和业务线               | 分别维护“机构归属”和“业务线归属”         | 不把任意 `name` 字段归入本类                                                           |
| 省、市、区县等粗粒度地域                   | 新增“行政区划信息”                       | 与精确地址、经纬度和轨迹分开分级                                                       |
| 日期、时间、时间戳字段                     | 统一“时间信息”内容正则                   | 不区分出生日期、业务时间、事件时间、有效期和维护时间；格式化日期、年月、时刻均归入本类 |
| 记录主键                                   | 新增“记录技术标识”                       | 主键采用受控前缀正则，不匹配任意 `*_id`                                                |
| 账号、地址、金额、诊断等已有类型的常见变体 | 扩充既有中英文词典                       | 保持具体业务规则的置信度高于通用元数据规则                                             |

备注、主题、自由文本、杂项编码、责任人别名、样例分组和阶段标识等字段，仅凭元数据无法稳定判断业务含义，继续保留为未分类并进入人工复核，避免为了提高命中率而强行归类。
